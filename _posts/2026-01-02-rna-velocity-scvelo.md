Single-cell RNA sequencing captures a snapshot of gene expression in individual cells, but biology is not static. Cells are constantly transitioning between states --- differentiating, activating, or becoming exhausted. **RNA velocity** gives us a way to infer the _direction_ and _speed_ of these transitions from a single time point, effectively turning a snapshot into a movie.

In this tutorial, we will walk through the full RNA velocity analysis pipeline using **scVelo** and **CellRank**, with an immunological focus on T cell differentiation and exhaustion trajectories.

---

## 1. What Is RNA Velocity?

The core insight behind RNA velocity is deceptively simple. When a gene is being actively transcribed, newly synthesized mRNA molecules contain **unspliced introns**. Over time, the spliceosome removes these introns, converting unspliced mRNA into mature **spliced** mRNA. Eventually, mRNA is degraded.

This gives rise to a simple kinetic model for each gene $$i$$:

$$
\frac{du_i}{dt} = \alpha_i - \beta_i u_i
$$

$$
\frac{ds_i}{dt} = \beta_i u_i - \gamma_i s_i
$$

where $$u_i$$ is unspliced mRNA abundance, $$s_i$$ is spliced mRNA abundance, $$\alpha_i$$ is the transcription rate, $$\beta_i$$ is the splicing rate, and $$\gamma_i$$ is the degradation rate.

At **steady state**, the ratio of unspliced to spliced mRNA is constant: $$u_i = \frac{\gamma_i}{\beta_i} s_i$$. Cells that deviate from this steady-state line are actively changing their expression of that gene. A cell with more unspliced mRNA than expected is _upregulating_ the gene; a cell with less is _downregulating_ it.

The **velocity** of gene $$i$$ is defined as:

$$
v_i = \beta_i u_i - \gamma_i s_i
$$

A positive velocity means the gene is being induced; a negative velocity means it is being repressed. By computing velocities across thousands of genes and projecting them onto a low-dimensional embedding, we can visualize the predicted future state of every cell.

## 3. Preprocessing: From Raw Counts to Velocity-Ready Data

### 3.1 Loading Data

RNA velocity requires both spliced and unspliced count matrices. These are typically generated by **velocyto** (producing `.loom` files) or **kb-python** (kallisto|bustools, producing an AnnData with layered counts).

**Option A: Loading from velocyto `.loom` files**

```python
# Load the loom file produced by velocyto
ldata = scv.read("sample1.loom", cache=True)
ldata.var_names_make_unique()

print(ldata)
# AnnData object with n_obs x n_vars
#     layers: 'spliced', 'unspliced', 'ambiguous'
```

**Option B: Loading from kb-python output**

kb-python (kallisto|bustools) directly produces an AnnData with `spliced` and `unspliced` layers via `ad.read_h5ad("kb_output/counts_unfiltered/adata.h5ad")`.

### 3.2 Merging with an Existing AnnData Object

If you have already performed QC, clustering, and UMAP with Scanpy, merge the velocity data into your existing AnnData:

```python
# Load your preprocessed scRNA-seq data
adata = sc.read_h5ad("tcell_preprocessed.h5ad")

# Merge loom data into existing AnnData
# This matches barcodes and adds spliced/unspliced layers
adata = scv.utils.merge(adata, ldata)

# Verify layers are present
print("Spliced counts:", adata.layers["spliced"].shape)
print("Unspliced counts:", adata.layers["unspliced"].shape)
```

### 3.3 Filtering and Normalization

scVelo provides its own preprocessing pipeline optimized for velocity estimation:

```python
# Filter genes by minimum counts in both spliced and unspliced layers
scv.pp.filter_and_normalize(
    adata,
    min_shared_counts=20,     # minimum total counts (spliced + unspliced)
    n_top_genes=2000,         # number of highly variable genes to retain
    retain_genes=None,        # optionally force-keep specific genes
    log=True                  # log-transform after normalization
)

# Compute PCA and neighbors (or use existing ones)
sc.tl.pca(adata)
sc.pp.neighbors(adata, n_pcs=30, n_neighbors=30)

# Compute first- and second-order moments for velocity estimation
scv.pp.moments(adata, n_pcs=30, n_neighbors=30)
```

The `moments()` step computes the local averages (first moments) and uncentered variances (second moments) of spliced and unspliced counts across each cell's neighborhood. These smoothed values are stored in `adata.layers['Ms']` and `adata.layers['Mu']`.

## 4. scVelo Analysis

### 4.1 The Stochastic Model

The **stochastic model** extends the basic steady-state model by accounting for the second-order moments (variance) of spliced and unspliced counts. It fits a linear regression for each gene's phase portrait while incorporating stochastic noise:

```python
# Estimate RNA velocity using the stochastic model
scv.tl.velocity(adata, mode="stochastic")

# Build the velocity graph (cell-cell transition probabilities)
scv.tl.velocity_graph(adata)

# Visualize velocity on UMAP embedding
scv.pl.velocity_embedding_stream(
    adata,
    basis="umap",
    color="cell_type",
    title="RNA Velocity Stream Plot (Stochastic)",
    legend_loc="right margin",
    save="velocity_stream_stochastic.png",
    dpi=150
)
```

### 4.2 The Dynamical Model

The **dynamical model** is scVelo's most powerful mode. Rather than assuming a single steady state, it solves the full system of ODEs for each gene, recovering the complete splicing dynamics including transcription rate ($$\alpha$$), splicing rate ($$\beta$$), and degradation rate ($$\gamma$$), along with a gene-specific **latent time**:

```python
# Recover full dynamics for each gene (this takes several minutes)
scv.tl.recover_dynamics(adata, n_jobs=8)

# Estimate velocity using the dynamical model
scv.tl.velocity(adata, mode="dynamical")

# Rebuild velocity graph with dynamical velocities
scv.tl.velocity_graph(adata)
```

Visualize the dynamical model results:

```python
scv.pl.velocity_embedding_stream(
    adata,
    basis="umap",
    color="cell_type",
    title="RNA Velocity Stream Plot (Dynamical)",
    legend_loc="right margin",
    save="velocity_stream_dynamical.png",
    dpi=150
)
```

### 4.3 Speed and Coherence Analysis

scVelo provides metrics that quantify how confidently we can assign velocity directions:

```python
# Velocity confidence (coherence of velocity field)
scv.tl.velocity_confidence(adata)

# 'velocity_confidence' ranges from 0 to 1
# Higher values mean more consistent velocity directions in local neighborhood

keys = ["velocity_length", "velocity_confidence"]
scv.pl.scatter(
    adata,
    c=keys,
    cmap="coolwarm",
    perc=[5, 95],
    save="velocity_confidence.png",
    dpi=150
)
```

The **velocity length** represents the speed of state change --- cells undergoing rapid differentiation have high velocity magnitudes. The **velocity confidence** measures the consistency of velocity directions in a cell's neighborhood --- high confidence means neighboring cells agree on the direction of change.

### 4.4 Latent Time

The dynamical model also infers a **latent time** that orders cells along their differentiation trajectory:

```python
# Compute latent time (requires dynamical model)
scv.tl.latent_time(adata)

scv.pl.scatter(
    adata,
    color="latent_time",
    color_map="gnuplot",
    size=80,
    title="Latent Time",
    save="latent_time.png",
    dpi=150
)
```

### 4.5 Driver Genes

We can identify genes whose velocity patterns most strongly drive specific transitions:

```python
# Rank genes by velocity in each cluster
scv.tl.rank_velocity_genes(
    adata,
    groupby="cell_type",
    min_corr=0.3  # minimum correlation with velocity
)

# Extract results as a DataFrame (rank_velocity_genes stores names as a structured numpy array)
df = pd.DataFrame(adata.uns["rank_velocity_genes"]["names"])
print(df.head(10))
```

Inspect the phase portraits of top driver genes:

```python
# Plot phase portraits for key T cell genes
top_genes = ["TOX", "TCF7", "GZMB", "PDCD1", "HAVCR2", "LAG3"]

scv.pl.velocity(
    adata,
    var_names=top_genes,
    color="cell_type",
    save="phase_portraits_tcell.png",
    dpi=150
)
```

In a T cell exhaustion dataset, you would expect to see:

- **TCF7** (TCF-1): high velocity in progenitor exhausted cells, decreasing as cells terminalize
- **TOX**: positive velocity in transitioning cells as TOX drives the exhaustion program
- **PDCD1** (PD-1), **HAVCR2** (TIM-3), **LAG3**: increasing velocity as inhibitory receptors accumulate

## 5. CellRank: Probabilistic Fate Mapping

While scVelo tells us the _direction_ of change, **CellRank** quantifies the _probability_ that each cell will reach a particular terminal state. It combines RNA velocity with transcriptomic similarity to build a robust transition matrix.

### 5.1 Initializing CellRank with Velocity

```python
from cellrank.kernels import VelocityKernel, ConnectivityKernel

# Create a velocity kernel from scVelo's velocity graph
vk = VelocityKernel(adata)
vk.compute_transition_matrix()

# Create a connectivity kernel (transcriptomic similarity)
ck = ConnectivityKernel(adata)
ck.compute_transition_matrix()

# Combine kernels: velocity provides direction, connectivity provides robustness
combined_kernel = 0.8 * vk + 0.2 * ck
```

### 5.2 Identifying Terminal States

CellRank uses the **GPCCA** (Generalized Perron Cluster Cluster Analysis) estimator to identify initial and terminal states:

```python
from cellrank.estimators import GPCCA

# Initialize the GPCCA estimator
g = GPCCA(combined_kernel)

# Compute the Schur decomposition
g.compute_schur(n_components=20)

# Plot the eigenvalue spectrum to choose the number of macrostates
g.plot_spectrum(real_only=True, save="eigenvalue_spectrum.png", dpi=150)
```

```python
# Compute macrostates (coarse-grained cell states)
g.compute_macrostates(n_states=5, cluster_key="cell_type")

# Visualize macrostates on UMAP
g.plot_macrostates(which="all", save="macrostates.png", dpi=150)

# Set terminal states (the absorbing states cells are moving toward)
g.set_terminal_states(
    states=["Exhausted_terminal", "Effector_memory", "Tex_progenitor"]
)
```

Once terminal states are defined, CellRank computes the probability that each cell will eventually reach each terminal state:

```python
# Compute absorption probabilities
g.compute_fate_probabilities()

# Visualize fate probabilities
g.plot_fate_probabilities(save="fate_probabilities.png", dpi=150)
```

## 6. Immunology Application: T Cell Trajectories

### 6.1 Naive to Effector to Exhaustion

In chronic viral infections and tumors, CD8+ T cells follow a well-characterized differentiation trajectory:

**Naive** $$\rightarrow$$ **Effector** $$\rightarrow$$ **Progenitor Exhausted (Tpex)** $$\rightarrow$$ **Terminally Exhausted (Tex)**

RNA velocity can recapitulate this trajectory from a single snapshot. Here is how to annotate and analyze it:

```python
# Define marker genes for each state
markers = {
    "Naive": ["CCR7", "LEF1", "TCF7", "SELL", "IL7R"],
    "Effector": ["GZMB", "PRF1", "IFNG", "TBX21", "CX3CR1"],
    "Tpex": ["TCF7", "SLAMF6", "XCL1", "ID3", "CXCR5"],
    "Tex_terminal": ["TOX", "PDCD1", "HAVCR2", "LAG3", "ENTPD1", "TIGIT"]
}

# Score each cell for each signature
for state, genes in markers.items():
    # Only use genes present in the dataset
    genes_present = [g for g in genes if g in adata.var_names]
    sc.tl.score_genes(adata, gene_list=genes_present, score_name=f"{state}_score")

# Visualize scores
sc.pl.umap(
    adata,
    color=["Naive_score", "Effector_score", "Tpex_score", "Tex_terminal_score"],
    ncols=2,
    cmap="RdYlBu_r",
    save="_exhaustion_scores.png"
)
```

```python
# Velocity analysis specifically on the exhaustion branch
# Subset to CD8+ T cells
adata_cd8 = adata[adata.obs["cell_type"].isin(
    ["Naive_CD8", "Effector_CD8", "Tpex", "Tex_terminal"]
)].copy()

# Recompute neighbors and moments on subset
sc.pp.neighbors(adata_cd8, n_pcs=30, n_neighbors=30)
scv.pp.moments(adata_cd8, n_pcs=30, n_neighbors=30)

# Run dynamical model on subset
scv.tl.recover_dynamics(adata_cd8, n_jobs=8)
scv.tl.velocity(adata_cd8, mode="dynamical")
scv.tl.velocity_graph(adata_cd8)

# Recompute UMAP for the subset
sc.tl.umap(adata_cd8)

scv.pl.velocity_embedding_stream(
    adata_cd8,
    basis="umap",
    color="cell_type",
    title="CD8+ T Cell Exhaustion Trajectory",
    save="cd8_exhaustion_velocity.png",
    dpi=150
)
```

### 6.2 Monocyte to Macrophage Differentiation

The same workflow applies to myeloid cells. In the tumor microenvironment, classical monocytes differentiate into tumor-associated macrophages (TAMs). Subset to myeloid populations (`Classical_Mono`, `Nonclassical_Mono`, `TAM_1`, `TAM_2`, `cDC`), recompute neighbors and moments, then run the dynamical model. The velocity stream plot will typically show directional flow from monocytes toward TAM clusters, revealing intermediate differentiation states that may not be apparent from clustering alone.

### 6.3 Identifying Branching Points

One of the most valuable applications of RNA velocity in immunology is detecting **fate decision points** where cells branch toward different functional states:

```python
# CellRank on the CD8+ subset to find branching
vk_cd8 = VelocityKernel(adata_cd8)
vk_cd8.compute_transition_matrix()

ck_cd8 = ConnectivityKernel(adata_cd8)
ck_cd8.compute_transition_matrix()

combined_cd8 = 0.8 * vk_cd8 + 0.2 * ck_cd8

g_cd8 = GPCCA(combined_cd8)
g_cd8.compute_schur(n_components=10)
g_cd8.compute_macrostates(n_states=4, cluster_key="cell_type")

# Identify terminal and initial states
g_cd8.set_terminal_states(states=["Tex_terminal", "Tpex"])
g_cd8.compute_fate_probabilities()

# Cells with intermediate fate probabilities are at the branching point
adata_cd8.obs["fate_entropy"] = -np.sum(
    adata_cd8.obsm["lineages_fwd"] * np.log(adata_cd8.obsm["lineages_fwd"] + 1e-10),
    axis=1
)

sc.pl.umap(
    adata_cd8,
    color="fate_entropy",
    cmap="inferno",
    title="Fate Decision Entropy\n(High = Branching Point)",
    save="_fate_entropy.png"
)
```

## 7. Stochastic vs. Dynamical Model: When to Use Which

Understanding when each model is appropriate is critical for correct biological interpretation:

| Feature                     | Stochastic                             | Dynamical                                             |
| --------------------------- | -------------------------------------- | ----------------------------------------------------- |
| **Speed**                   | Fast (minutes)                         | Slow (hours for large datasets)                       |
| **Steady-state assumption** | Yes (single steady state per gene)     | No (models full induction/repression kinetics)        |
| **Latent time**             | Not available                          | Yes                                                   |
| **Rate parameters**         | Only $$\gamma$$ (degradation)          | $$\alpha$$, $$\beta$$, $$\gamma$$ per gene            |
| **Multi-lineage**           | Limited accuracy                       | Better at branching trajectories                      |
| **Best for**                | Quick exploration, simple trajectories | Publication-quality analysis, complex differentiation |

In practice, start with the stochastic model for quick exploration, then switch to the dynamical model if the results look reasonable. Compare velocity confidence between models using `scv.tl.velocity_confidence()`. One important caveat: both models assume that splicing dynamics reflect the _current_ direction of transcriptional change. In systems with rapid transitions or strong post-transcriptional regulation (e.g., miRNA-mediated degradation in activated T cells), velocity estimates may be noisy. Always validate against known biology.

## 8. Key Takeaways

1. **RNA velocity exploits splicing kinetics** to infer the future state of individual cells from a single time-point measurement. The ratio of unspliced to spliced mRNA reveals whether genes are being induced or repressed.

2. **Start with the stochastic model** for initial exploration, then switch to the **dynamical model** for publication-quality results. The dynamical model recovers per-gene kinetic rates and latent time without requiring a steady-state assumption.

3. **CellRank extends velocity** by computing probabilistic fate maps. Rather than relying on visual inspection of stream plots, CellRank provides quantitative absorption probabilities for each terminal state.

4. **Immunological applications are particularly well-suited** to RNA velocity because T cell differentiation follows well-characterized trajectories with known marker genes that can validate computational predictions.

5. **Latent time and driver gene analysis** provide actionable biological insights. Latent time orders cells along trajectories without prior assumptions, and driver genes highlight regulators of state transitions (e.g., TOX as a driver of T cell exhaustion).

6. **Fate entropy identifies branching points** where cells commit to different lineages. These bifurcation points are often the most therapeutically relevant --- for example, understanding what pushes a T cell toward terminal exhaustion versus maintenance of a progenitor-like state could inform checkpoint immunotherapy strategies.

7. **Always validate computationally** inferred trajectories against known biology. RNA velocity is a powerful hypothesis-generating tool, but artifacts from ambient RNA, doublets, or genes with complex post-transcriptional regulation can produce misleading results. Cross-reference velocity directions with established differentiation markers, time-course data, or lineage tracing experiments when available.
